# Spec: the shared query language, its validator, the search worker and the filter form (QUERY)

**IS NOW** = true of the code today (⚠ = known defect) · **SHOULD BE** = agreed target.
Format: [ADR-0001](../decisions/0001-spec-driven-development.md). Decision:
[ADR-0034](../decisions/0034-kanban-boards.md). Issues: #596 (epic), #597, #598, #599.

One query language is read by the board lanes (BOARD-002), the sidebar search (NAV-007) and the
picker (NAV-022). Every query is checked before it runs, runs on a background worker and ends
within a budget. The same filter and sort form edits it everywhere. The language, the validator
and the worker are true now (#597, #598); the lanes and the form are planned work.

## The language

| ID | Rule | Status | Code | Test |
|---|---|---|---|---|
| QUERY-001 | **Operators** (#597). `AND`, `OR` and `NOT` are operators only in upper case, so "salt and pepper" stays a text search. Parentheses group. Precedence is NOT, then AND, then OR. Two terms side by side are AND. `-x` is `NOT x`. A run of plain words with nothing between them (no field, no `-x`, no operator) is one text term, a phrase, as the search has always taken it, so "salt and pepper" is one pattern and "milk run #todo" is the text "milk run" AND the tag. `NOT` and `-` take one term or one group. A quoted word (`"AND"`, `"a (b)"`) is text whatever is inside it. | IS NOW | `search_all/query.rs` (`Checked::search`, `parse`) | `query.rs::query_001_operators_are_upper_case_and_precedence_is_not_and_or`, `query.rs::query_001_lower_case_words_are_text_and_a_run_of_words_is_one_phrase`, `query.rs::query_001_a_minus_is_not`, `matcher.rs::query_004_a_note_matches_as_a_whole_not_a_line` |
| QUERY-002 | **Fields** (#597). `#tag` matches a tag (`#a` matches `#a/b` too); `prop:value` matches any front-matter key, case ignored, a list property when one of its items is the value (`status:doing`, `type:drawing`); `path:Folder/` matches the path prefix; `links:[[X]]` matches notes that link to X (by name, as the vault reads links); `blocked` and `blocking` match the dependency state: a note is **blocked** while a note named in its `blocked-by:` (a comma-separated list of `[[links]]`, or a list of lines) exists and is not done, and **blocking** while it is not done and a note that is not done names it; a note is done with `status: done` (`search_all/deps.rs`, the one place #603 extends, BOARD-023, BOARD-024); every other word is text. A word with a colon and a value after it is a property when its key starts with a letter, so `12:30`, `http://x` and `TODO: fix` stay text. The words `blocked` and `blocking` are fields; quote them to search the word. | IS NOW | `search_all/query.rs`, `search_all/matcher.rs`, `search_all/deps.rs` | `query.rs::query_002_fields`, `matcher.rs::query_002_fields_select_notes`, `matcher.rs::query_002_blocked_and_blocking_follow_the_blockers_that_are_not_done`, `matcher.rs::query_002_a_blocker_that_is_done_or_missing_blocks_nothing`, `deps.rs::blocked_by_is_a_list_of_links_in_any_front_matter_shape`, `deps.rs::a_note_is_done_with_status_done`, `search_all.rs::query_004_fields_select_notes_and_text_terms_find_the_lines_inside_them` |
| QUERY-003 | **Dates** (#597). `due:` takes a date (`due:2026-12-01`), `today`, a comparison with a day relative to today (`due:<+7d`, `due:>-3d`, also `<=` and `>=`; `<` and `>` leave the day itself out) or `due:overdue` (before today). The date is the `due:` property of the front matter (a time after the date is left out); a note without one matches none of these. A bad date is a syntax error (QUERY-008). | IS NOW | `search_all/query.rs`, `search_all/matcher.rs` | `query.rs::query_003_dates_and_ranges`, `matcher.rs::query_003_due_compares_with_today` |
| QUERY-004 | **Text** (#597). A word that is no field is text matched with the wildcards `*` and `?` of NAV-023; a pattern of wildcards alone is a syntax error. The sidebar and the picker select notes by the whole query and then list the lines that have a text term that is not under a NOT, so a plain text query lists what it listed before, and a query without a text term lists the notes. In a board lane the text and the other terms match a note as a whole, not a line (`Run::match_notes`): `milk AND pepper` matches a note that has the two words on different lines. | IS NOW | `search_all/query.rs`, `search_all/matcher.rs` (`Run::note_matches`, `Run::match_notes`), `search_all.rs` (`scan_notes`) | `query.rs::query_004_text_has_wildcards_in_lower_case`, `matcher.rs::query_004_a_note_matches_as_a_whole_not_a_line`, `search_all.rs::query_004_fields_select_notes_and_text_terms_find_the_lines_inside_them` |
| QUERY-005 | **The prefixes of NAV-050 keep working** (#597). `f:`, `m:` and `s:` at the start of the query choose the sources as before; the rest is read as this language. A board lane searches notes only, so a prefix there is a syntax error (`Checked::lane`, used by the lanes of #601). | IS NOW | `search_all/query.rs` (`Checked::search`, `Checked::lane`) | `query.rs::query_005_a_prefix_chooses_the_sources_and_a_lane_refuses_it`, `search_all.rs::query_005_a_prefix_still_chooses_the_sources_and_the_rest_is_the_language` |
| QUERY-006 | **A source says which fields it supports** (#597). Notes take every term. Mail and posts take text terms and their own field words (`from:`, …, MAIL-012, SOC-031), side by side (AND); `OR`, `NOT`, `#tag`, `path:`, `due:`, `links:`, `blocked` and any other property are not supported there. A query with a term a source lacks skips that source and says so ("Mail: `status:` not supported", under the source buttons, for the sources that are listed); it is not shown as an empty result and not counted. | IS NOW | `search_all.rs` (`foreign_text`, `Skipped`, `Found::skipped`, `Results::skipped`), `search_sources.rs` (`notices`) | `search_all.rs::query_006_a_source_without_the_field_is_skipped_and_says_so`, `search_sources.rs::the_notices_say_why_the_query_is_refused_what_was_skipped_and_that_the_search_stopped` |

## Validator and budget

| ID | Rule | Status | Code | Test |
|---|---|---|---|---|
| QUERY-007 | **Parsed and checked first** (#597). Every query is parsed into a tree and checked before anything runs. The picker and the sidebar hand the check to the search with the query (`Query::checked`); a search without one checks the text itself, and a text that does not pass finds nothing. | IS NOW | `search_all/query.rs` (`Checked`), `search_all.rs` (`Query::check`, `search_within`) | `search_all.rs::query_007_the_check_of_the_view_goes_with_the_query_to_the_search` |
| QUERY-008 | **Syntax errors stop the search** (#597). Unbalanced parentheses, a dangling operator, an empty group, an unclosed quote, a field without its value or in the wrong shape (`links:`, `path:`) and a bad date or priority value are errors (a word with a colon is a property, so there is no unknown field; `priority:` takes only `highest`, `high`, `medium`, `low`, `lowest`, VAULT-047). The error is underlined in the text box with a short reason under it, nothing runs, and the last valid result stays shown (`Ask::invalid`). | IS NOW | `search_all/query.rs` (`QueryError`), `search_all.rs` (`Results::refresh`), `search_sources.rs` (`error_layouter`, `notices`), `picker.rs`, `search_panel.rs` | `query.rs::query_008_syntax_errors_name_their_place_and_reason`, `search_all.rs::query_008_a_text_with_a_syntax_error_asks_nothing_and_the_last_valid_list_stays`, `picker.rs::a_query_with_a_syntax_error_asks_nothing_and_the_last_valid_list_stays`, `search_panel.rs::the_sidebar_shows_a_syntax_error_and_keeps_the_last_valid_list`, `search_sources.rs::the_text_box_underlines_the_error_of_the_query_and_parses_once_per_text` |
| QUERY-009 | **Limits** (#597; these are the spec's numbers). A query has at most 500 characters, 32 terms (a run of plain words is one term) and nesting depth 8 (parentheses and `NOT`); a text pattern has at most 8 `*`. A query over a limit is a syntax error (QUERY-008). | IS NOW | `search_all/query.rs` (`MAX_QUERY_CHARS`, `MAX_TERMS`, `MAX_DEPTH`, `MAX_STARS`) | `query.rs::query_009_limits_are_syntax_errors` |
| QUERY-010 | **A work budget per search** (#597). A search counts the characters it compares (every step of a wildcard comparison, a line of plain text by its length) and has a time limit (`search_all::CHAR_BUDGET`, `TIME_BUDGET`: 400 million characters, 5 seconds). The budget is checked next to the cancel flag of QUERY-017, per line, and inside one line for a wildcard pattern. When it is used up the search ends and the result is partial, marked "Stopped early, narrow the query" under the source buttons. The reason: `matches_at` retries at every start position, so `*a*a*a*…b` costs time quadratic in the line. | IS NOW | `search_all.rs` (`find_wild`, `search_within`), `search_all/matcher.rs` (`Budget`, `Run`), `search_sources.rs` (`STOPPED_EARLY`) | `matcher.rs::query_010_a_search_ends_early_when_the_budget_is_used_up`, `search_all.rs::query_010_a_search_that_uses_up_its_budget_is_partial_and_says_so` |
| QUERY-011 | **A property test** (#597, DEV-042). For every input, the checker rejects it or reads it within the limits, and the search of the notes ends within the budget (QUERY-010), and nothing panics. The generator (`property_test_support::query_text`) mixes the pieces of the language in any order with arbitrary text. | IS NOW | `search_all/query.rs`, `search_all/matcher.rs`, `property_test_support.rs` | `query.rs::query_011_any_text_is_refused_or_read_within_the_limits`, `matcher.rs::query_011_any_query_is_refused_or_ends_within_the_budget_and_never_panics` |
| QUERY-012 | **A bad lane query stays in its lane** (#597, #601). A board lane whose saved query fails the check (QUERY-008) shows the error in its header and is empty; the rest of the board works. | SHOULD BE | `board/` (planned) | — |
| QUERY-013 | **Checked once per text** (#597). A query is parsed and checked when its text changes, not every frame; the result is kept with the text (`query::Cache`, one per view; the text box and the search ask it). | IS NOW | `search_all/query.rs` (`Cache`) | `query.rs::query_013_a_text_is_parsed_once_not_every_frame`, `picker.rs::a_query_with_a_syntax_error_asks_nothing_and_the_last_valid_list_stays`, `search_panel.rs::the_sidebar_shows_a_syntax_error_and_keeps_the_last_valid_list`, `search_sources.rs::the_text_box_underlines_the_error_of_the_query_and_parses_once_per_text` |
