### Fixed

- A Word file (or a CalDAV answer) whose XML is nested thousands of levels deep no longer crashes Shale with a stack overflow: the Word import refuses it at once with "the XML is nested too deeply (more than 256 levels)", the Word export gives an error, and the calendar reports that the answer cannot be read (#503).

### Added

- For developers: `scripts/validate-docx.sh <file.docx>…` checks the parts of a Word file against Microsoft's WordprocessingML schema; the Word export tests check every file they write with it (the schemas are fetched into a cache outside the repository, the check is skipped without them). `scripts/docx-corpus.sh` runs the round trip, the schema check and a page count on 50 real-world Word files of pandoc, LibreOffice, Apache POI and the Open XML SDK and prints a table (#497).
- The fixture `styled.docx` of the import tests is now valid WordprocessingML (its Heading 1 had `w:pageBreakBefore` after `w:spacing`) (#497).
